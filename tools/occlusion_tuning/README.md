# Проверка occlusion query на самоокклюзию

Автономный тест для `Renderer::issue_occlusion_query`/`render_chunks` — того самого запроса,
который решает, рисовать ли секцию в СЛЕДУЮЩЕМ кадре. Использует настоящий GLFW+OpenGL (не
заглушку), у себя на машине запускается напрямую (есть GPU и дисплей). В headless/CI —
через Xvfb + `LIBGL_ALWAYS_SOFTWARE=1` (софтверный рендерер llvmpipe), см. пример ниже.

## Что именно проверяется

Секция тестируется на occlusion query АФТЕР того, как в этом же кадре уже нарисована вся
непрозрачная геометрия — включая, если секция была видима в прошлом кадре, её же
собственную. Если рядом с ней (в её экранной проекции) нет НИКАКОЙ ДРУГОЙ геометрии —
типичный случай: плоская стена/пол, целиком заполняющие вид, без клочка неба или проёма по
краям — единственное, с чем сравнивается её бокс, это она сама.

Здесь есть развилка, и она была причиной бага:
- Сместить бокс так, чтобы самосравнение **надёжно проваливалось** ("это не в счёт, я не
  окклюдер сам себе") — интуитивно кажется правильным, но проваленный тест = "не рисовать
  в следующем кадре" = убрать из глубинного буфера ЕДИНСТВЕННОЕ, с чем можно было сравнивать
  = в следующем кадре сравнивать ПРОСТО НЕ С ЧЕМ = тест проходит = снова рисовать = снова
  проваливается… Чистый, детерминированный цикл "кадр через кадр", безо всякого дрожания
  камеры — подтверждено этим тестом (см. `previous_broken` в выводе: `01010101`).
- Сместить бокс так, чтобы самосравнение **надёжно проходило** — тогда "не с чем сравнивать"
  просто означает "остаётся видима", никакого цикла. Настоящий внешний окклюдер (холм,
  соседний чанк) всё равно закрывает на многие блоки, а не на волосок, так что небольшой сдвиг
  в эту сторону не портит настоящую окклюзию — это тоже проверяется тестом отдельным блоком
  ("холм перед секцией").

Именно поэтому в `issue_occlusion_query` и `render_chunks` бокс теперь **расширяется** наружу
(а не сжимается) и `glPolygonOffset` со знаком **минус** (а не плюс).

## Сборка и запуск

```
./build.sh
./occlusion_test
```

Headless-пример (если нет дисплея под рукой):
```
Xvfb :77 -screen 0 800x600x24 &
export DISPLAY=:77
export LIBGL_ALWAYS_SOFTWARE=1
./occlusion_test
```

## Как читать вывод

Для каждой камеры и каждой стратегии смещения — 8 симулированных кадров подряд (камера не
меняется) в виде строки `01101...`, где `1` = секция была видима в этом кадре. Если в
последовательности встречаются и переходы `0→1`, и `1→0` — тест помечает её `<<< МИГАЕТ`.
Отдельный блок в конце проверяет, что реальный внешний окклюдер по-прежнему стабильно (`00000000`)
прячет секцию при любой из стратегий.

Если будете менять `occlusion_box_bias` или `glPolygonOffset` в `Renderer.cpp` — добавьте свою
стратегию в список `strategies` здесь и прогоните перед тем, как переносить числа в движок.
